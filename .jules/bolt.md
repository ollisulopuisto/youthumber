# Bolt's Journal - Performance Learnings

## 2026-11-01 - Fast image mask compositing with typed array bulk cloning
**Learning:** During speaker mask refinement (threshold / choke slider adjustments), `applyMaskToImageData` executes repeatedly over full-HD RGBA buffers (2,073,600 pixels). Manually indexing and copying each RGB channel per pixel in JavaScript (`output[idx] = sourceRgba[idx]`, etc.) causes over 6.2 million array read/write operations in the interpreter loop. Initializing `output = new Uint8ClampedArray(sourceRgba)` lets the engine delegate RGB copying to a single native bulk memory copy (memcpy), allowing the JS loop to only modify the alpha channel (`idx + 3`). Additionally, fast-pathing the common case (`opacity === 1` and `sourceAlpha === 255`) skips floating-point division and rounding, dropping loop execution time from ~50ms to ~32ms per full-HD frame (~36% faster).
**Action:** When performing pixel-manipulation passes that modify only a subset of channels (such as alpha masking or channel tinting), use bulk typed-array cloning or 32-bit views before looping, rather than copying all channels element-by-element in JS.

## 2026-11-03 - Pointer progression and row-offset hoisting in alpha hit-testing
**Learning:** `alphaMapFor` generates a 512x512 downscaled alpha map for per-pixel pointer hit testing. Calculating `pixels[i * 4 + 3]` per pixel performs 262k multiplications per map extraction. Stepping linearly with `let i = 0, idx = 3; i < alpha.length; i++, idx += 4` drops map extraction time from ~176ms to ~98ms per 200 maps (~44% faster). Additionally, in `isMapTransparent`, hoisting `rowOffset = py * width` out of the inner loop over `px` removes repeated row multiplications on every tested cursor coordinate, reducing hit-test evaluation time by ~14%.
**Action:** In pixel extraction and 2D grid hit-testing loops, prefer linear index pointer progression and hoist row-offset calculations out of nested column loops.

## 2026-11-03 - Pre-projecting aspect coordinates and typed array flattening in 2D Voronoi shader
**Learning:** In procedural generation shaders (`procgen.js` Voronoi / Facets), computing distances across 28–47 sites per pixel in a 640×360 pass (230,400 pixels) causes over 8.7 million iterations of `(s.x - u) * aspect` multiplications and object property accesses. Pre-scaling site x coordinates by aspect up front (`siteSx = new Float64Array(n)`) and storing sites in flat typed arrays allows calculating `uAspect = u * aspect` once per pixel and directly evaluating `dx = siteSx[i] - uAspect`. This reduced average 1280×720 render time from 77.43ms to 61.50ms (~20.6% faster).
**Action:** When evaluating geometric distance fields against point sets across image pixels, pre-scale coordinate axes to eliminate inner-loop aspect ratio multiplications and pack point attributes into flat typed arrays.

## 2026-11-04 - Scanline y-distance hoisting in 2D Voronoi shader
**Learning:** Even after flattening site arrays in `voronoi` (`procgen.js`), computing vertical distance per site `dy = siteY[i] - v` and squaring it (`dy * dy`) inside the per-pixel shade function still resulted in 8.7M+ redundant floating-point multiplications per 640×360 pass, since `v` remains identical across all columns of a row. Pre-allocating `dy2 = new Float64Array(n)` and updating it only when `v !== lastV` (once per row) eliminated $n \times (lw - 1)$ multiplications and subtractions, reducing Full HD render time from ~49.2ms to ~40.3ms (~18% faster).
**Action:** In 2D per-pixel procedural shaders where a coordinate dimension ($v$ or $u$) is constant across a raster scanline or chunk, precompute axis-specific distances into a typed array at the row boundary rather than re-evaluating them at every individual pixel.

## 2026-11-05 - Bidirectional scanline bounding and search space pruning in mask bbox detection
**Learning:** In `computeCutoutBBox` (`autoFrame.js`), locating subject bounding boxes across downscaled cutout buffers (e.g. 240×135 = 32,400 pixels) previously scanned all pixels exhaustively, performing `(y * sampleW + x) * 4 + 3` index arithmetic and updating coordinates on every single non-transparent pixel. By breaking the search into top-down and bottom-up raster scans with linear pointer progression (`idx += 4`) to establish `minY` and `maxY`, then scanning inward along rows only within `[minY, maxY]` and narrowing `[0, minX)` and `(maxX, sampleW - 1]` with immediate breaks, the search space collapses drastically. This reduced execution time from 163.11ms to 65.03ms per 1,000 passes (~60% faster, 2.51x speedup).
**Action:** When finding bounding extents on 2D binary or thresholded raster masks, use bidirectional row scans to bound vertical extents first, then prune the inner horizontal search intervals using monotonic bounds and early breaks instead of an exhaustive 2D grid scan.

## 2026-11-06 - Row hoisting and squared radial boundary pruning in procedural halftone generation
**Learning:** In procedural decor generators (`halftone` in `decor.js`), generating grid circles computed row parity `(Math.round(y / spacing) % 2) * (spacing / 2)` and Euclidean distance `Math.hypot(x + offset - cornerX, y - cornerY)` repeatedly inside the innermost horizontal loop over `x` (up to ~3,000 grid iterations per frame). Because `y - cornerY` and the row offset remain invariant across all columns in a row, hoisting `dy2 = (y - cornerY)^2` and `offset` outside the inner loop eliminates redundant floating-point operations. Testing `dx^2 + dy2 > reach^2` allows skipping out-of-bounds dots before evaluating expensive square root / hypotenuse calculations, reducing generation time from ~202ms to ~46ms per 2,000 passes (a 4.4x speedup, ~77% faster).
**Action:** In 2D grid or particle field generators with radial cutoffs, hoist row-level offsets and vertical squared distances out of the nested column loop, and check squared Euclidean distances against squared bounds before computing square roots.

## 2026-11-07 - Two-pass raster Union-Find replaces queue BFS in mask connected components
**Learning:** During person cutout segmentation and matting, `keep_largest_region` cleans up stray objects (e.g., floating microphone or chair artifacts) on downscaled binary mask buffers (~130,000 pixels). The previous implementation performed a queue-based breadth-first search (`collections.deque`), allocating over 170,000 Python `(y, x)` coordinate tuples and performing ~350,000 2D NumPy array index operations per call. Replacing this with a two-pass raster scan using disjoint-set (Union-Find) with path compression and vectorized `np.bincount` component tallying eliminates all queue and tuple allocations, dropping execution time on full-HD masks from 242.45ms to 110.50ms (a 54.4% reduction, 2.19x speedup).
**Action:** When performing 4-connected binary region labeling in pure Python without native C-extensions like SciPy, prefer two-pass raster scanning with Union-Find and NumPy vectorization over queue-based BFS traversals to avoid per-pixel Python object allocation overhead.

## 2026-11-08 - Precomputing octave coordinates and row hoisting in fractional Brownian motion (fbm)
**Learning:** In the `contours` procedural generator (`procgen.js`), evaluating 3 octaves of value noise per raster pixel across a 962×542 grid (521,404 pixels) previously recomputed fractional Brownian motion (fbm) x-coordinate scaling `ox + (x / lw) * scale * (w / h)` and y-coordinate scaling `oy + (y / lh) * scale` inside the innermost horizontal loop, resulting in over 1.5 million redundant floating-point multiplications and divisions per pass. Precomputing the 3 octave x-coordinates into `Float64Array` typed arrays across the column stride and hoisting the row-level y-coordinate calculations and row-offset multiplications out of the inner loop reduces average 1280×720 render time from 133.58ms to 105.07ms (~21.3% faster).
**Action:** In multi-octave 2D procedural noise or shader generators evaluated over regular grid buffers, precompute column x-coordinates across all octaves into flat typed arrays and hoist scanline y-coordinate evaluations to the outer row boundary.

## 2026-11-09 - Direct scanline rasterization replaces callback dispatch in grid procedural generator
**Learning:** In procedural shaders that pre-calculate discrete grid state (like the 2D contour bands in `contours` in `procgen.js`), delegating pixel shading to `pixelPass`'s generic `shade(u, v, lw, lh)` callback executed 518,400 closure calls per 960×540 buffer. Each call performed float divisions `(x / lw, y / lh)`, recovered grid coordinates with `Math.round(u * lw, v * lh)`, and returned 3-element RGB arrays (`[r, g, b]`) destructured in the outer loop, generating over 518k short-lived array allocations. Replacing the callback pattern with direct scanline rasterization into `ImageData.data` using hoisted row offsets (`rowOffset = y * stride`, `rowOffsetDown2 = (y + 2) * stride`) and linear pointer progression (`o += 4`) cuts raster loop time from 18.65ms to 8.99ms (~51.8% faster, 2.07x speedup).
**Action:** When a procedural generator precomputes grid or band lookups, rasterize directly into the ImageData buffer using hoisted row pointers and linear destination stepping instead of piping through per-pixel floating-point callback abstractions that allocate color arrays.

## 2026-11-10 - Direct scanline rasterization and coordinate precomputation in Voronoi shader
**Learning:** In the `voronoi` ('Facets') procedural background generator (`procgen.js`), rasterizing 230,400 pixels across a 640×360 buffer previously routed each pixel through `pixelPass`'s `shade(u, v)` callback, performing 230k closure calls, per-pixel coordinate scaling `u * aspect` and `x / lw`, and temporary 3-element array allocations inside `rgbPaletteAt`. Precomputing `uAspect` across columns into a `Float64Array`, rasterizing directly into `ImageData.data` with linear pointer progression (`o += 4`), and inlining palette component blending reduced 1280×720 Voronoi median render time from 54.68ms to 45.15ms (~17.4% faster, 1.21x speedup) while removing the obsolete `pixelPass` helper.
**Action:** In per-pixel procedural texture shaders, eliminate generic per-pixel callback abstractions in favor of direct ImageData scanline rasterization, precompute column-wise coordinate projections in typed arrays, and inline palette interpolation to prevent per-pixel short-lived array allocations.

## 2026-11-11 - Separable BoxBlur dilation replaces unseparated MaxFilter in mask combination
**Learning:** In `combine_masks` (`youthumber/matting.py`), expanding the core person mask by `reach` (typically reach=10 on downscaled 500-wide buffers) previously called `ImageFilter.MaxFilter(2 * reach + 1)`. In PIL, `MaxFilter` is an unseparated rank filter that evaluates $(2 \times reach + 1)^2$ (e.g. $21 \times 21 = 441$) operations per pixel, taking ~167ms for that step alone. Because the input mask is strictly binary (0 or 255), morphological dilation across a rectangular window is mathematically identical to checking if the moving box sum is strictly positive: `img.filter(ImageFilter.BoxBlur(reach)).point(lambda v: 255 if v > 0 else 0)`. `BoxBlur` in PIL uses separable $O(1)$ running sums in C, cutting filter execution from ~167ms to ~1.3ms and dropping full-HD `combine_masks` median execution time from 347.38ms to 162.41ms (a 53.2% reduction, 2.14x speedup).
**Action:** When performing rectangular morphological dilation (max-filter) on binary masks (0/255) in PIL with radius `r <= 10`, replace `ImageFilter.MaxFilter(2*r+1)` with separable `ImageFilter.BoxBlur(r).point(lambda v: 255 if v > 0 else 0)` to eliminate $O(r^2)$ kernel overhead. Do NOT use it for `r >= 11`: a lone white pixel blurs to 255 / (2r+1)^2 < 0.5 and rounds to 0, so BoxBlur drops it while MaxFilter keeps it. `matting._dilate_binary` enforces this and falls back to MaxFilter; production reach is capped at 10 by `REACH_WORK_WIDTH` (500) x `PERSON_REACH_FRACTION` (0.02).
